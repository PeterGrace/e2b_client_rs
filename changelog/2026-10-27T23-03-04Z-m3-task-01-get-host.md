# M3 Task 1: `get_host` (issue #60)

Plan: `docs/superpowers/plans/2026-10-27-milestone-3-lifecycle-parity.md`, Task 1.
Claims: CLM-0028 (S1), CLM-0154 (S4).

## What changed

- `ConnectionConfig::sandbox_host(sandbox_id, sandbox_domain, port)`: the
  SDKs' `ConnectionConfig.get_host`, `<port>-<sandbox_id>.<domain>`, with the
  domain the API reported for the sandbox, else the configured domain.
  `E2B_SANDBOX_URL` does not change it, as in both SDKs.
- `Sandbox::get_host(port)` delegates to it with the handle's reported
  domain.
- The private helper behind the envd URLs, which hard-coded the envd port,
  is now `host_name(port, sandbox_id, domain)`; `envd_rpc_url` and
  `envd_direct_url` pass `ENVD_PORT`. Their output is unchanged.
- Unit tests `sandbox_host_uses_the_sandbox_domain_then_the_configured_one`
  (config) and `get_host_follows_the_reported_domain` (sandbox), a doctest on
  `sandbox_host`, and the live test
  `clm_0028_get_host_reaches_a_port_in_the_sandbox`, which serves a file with
  `python3 -m http.server 8000` and fetches it at `https://<get_host(8000)>/`.
- Docs: a `get_host(port)` row in `docs/protocol-notes.md` ("envd
  addressing"), the CLM-0154 row in `docs/verification/s4-evidence-map.md`,
  and that file's intro now names CLM-0152 and CLM-0154 to CLM-0167.

## Why the plan was corrected

- `cargo test --lib sandbox_host get_host` (Task 1 Steps 2 and 4) and
  `cargo test --test rest_lifecycle pause_ connect_ v1_` (Task 7 Step 2) are
  usage errors: cargo accepts one positional filter, and several go after
  `--`. Fixed inline with a dated note.
- The "envd addressing" table has two columns, so the plan's three-cell row
  became "`get_host(port)`: <format> | <citations>".
