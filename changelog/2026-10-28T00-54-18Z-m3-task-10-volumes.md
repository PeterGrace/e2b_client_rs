## Why

**The token never reaches a log.** It is a `SecretString`, and `Volume`'s
`Debug` prints only the ID, name and domain. A mock test checks the
formatted volume does not contain the token.

**One mount per path.** The SDK takes the mounts as a dict from path to
volume, so a second mount at a path replaces the first. `volume_mount` does
the same, in the first one's place, as a dict assignment keeps the key's
position. The plan's plain `push` would have sent both.

**`VolumeNotFound` only for 404.** As in the SDK, other statuses stay
`Error::Api`, including hosted E2B's 400 `Invalid volume ID` for an ID that
is not a UUID.

**The volume sweep kills the run's sandboxes first.** Hosted E2B refuses to
delete a snapshot while a sandbox made from it runs; whether it does the same
for a mounted volume could not be checked (see below), so the sweep does what
the snapshot sweep does.
