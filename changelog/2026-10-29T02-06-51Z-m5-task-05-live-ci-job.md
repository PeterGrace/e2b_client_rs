# M5 Task 5: The live CI job (issue #127)

Plan: `docs/superpowers/plans/2026-10-28-milestone-5-release.md`, Task 5
(decision 1). Backs CLM-0123. Closes #127.

## Why

The live suite has only ever run from a developer's machine with a `.env`.
CLM-0123 asks for a CI job that runs it against hosted E2B. A run creates
about 80 billed sandboxes, so the job is manual only (`workflow_dispatch`),
with no schedule.

## What changed

- `.github/workflows/live.yml` (new): one job, `just test-live hosted`, on
  `ubuntu-latest` with a 45-minute limit and a `live-hosted` concurrency
  group (one run at a time; two would share the team's sandbox quota).
  `permissions: contents: read`.
  - `E2B_API_KEY_HOSTED` comes from the repository secret and is set only on
    the three steps that read it (the "secret is set" check, the live tests,
    and the run-log check), never as job-level `env`, so the third-party
    setup actions never see it.
  - Before upload, the run log is searched for the key (`grep -F`); a log
    that contains it is deleted and the step fails. GitHub masks secrets in
    the job log but not in uploaded files.
  - The log is uploaded as the artifact `live-hosted-log`, kept 30 days,
    whether the tests passed or not.
- `CONTRIBUTING.md`: a "Live CI job" section: how to start it, the secret a
  maintainer sets, the artifact, the cost.
- The plan: Task 5's harness line reference corrected (dated note).

## The harness in CI

`tests/live_support/mod.rs` reads each setting from the process environment
first and from `.env` only as a fallback (`setting`, lines 61-76), so
`E2B_API_KEY_HOSTED` from the step's `env` is enough on a runner with no
`.env`. `client()` (lines 111-134) asserts that `E2B_API_KEY`,
`E2B_API_URL`, `E2B_DOMAIN` and `E2B_SANDBOX_URL` are unset; none is set in
the workflow. The run log's `_stamp` header reads `dirty: no` on a fresh
checkout, since `target/` is in `.gitignore`.

Swatinem/rust-cache was checked for a stale log coming back from the cache:
at the pinned SHA its `cleanTargetDir` (`src/cleanup.ts`) removes every
plain file in a non-profile directory under `target/` before saving, so
`target/live-logs/*.log` is never cached and the artifact holds only this
run's log.
