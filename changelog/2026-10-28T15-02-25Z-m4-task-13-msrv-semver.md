# M4 Task 13: MSRV 1.89 and the semver policy (issue #96)

Plan: `docs/superpowers/plans/2026-10-28-milestone-4-api-stability.md`, Task 13.
Claim: CLM-0121.

## The MSRV and how it was found

- `cargo +1.89 check --all-targets --locked` finishes with no warnings.
- `cargo +1.88 check --all-targets --locked` fails before compiling anything:
  `uuid@1.29.0 requires rustc 1.89.0`. So 1.89 is the real floor, set by the
  highest dependency `rust-version` (uuid 1.29.0), as the plan's "Verified
  facts" say.

`Cargo.toml` now has `rust-version = "1.89"`. `Cargo.lock` is unchanged.

## CI

`.github/workflows/ci.yml` gains a job `msrv` ("MSRV (Rust 1.89)"):
`dtolnay/rust-toolchain@master` with `toolchain: "1.89"`, then
`cargo check --all-targets --locked`. `--locked` checks the committed
`Cargo.lock`, which is what a git dependency resolves to. The pinned toolchain
must equal `rust-version`; a later MSRV change edits both.

## The policy

The README's new "Versioning" section:

- semver; before 1.0 a minor release may break the API, a patch release never
  does;
- raising the MSRV is a minor release, never a patch release;
- the public dependencies, each with where it appears in the API: `bytes` 1,
  `chrono` 0.4, `secrecy` 0.10 (re-exported as `e2b_client::secrecy`),
  `serde` 1, `serde_json` 1, `tokio` 1 and `url` 2. Every other dependency,
  reqwest included, is private (`Error::Transport` holds `TransportError`).

Each "Where it appears" cell was checked against `src/lib.rs`'s re-exports and
the public signatures. The README's install paragraph now says Rust 1.89 or
newer. `CONTRIBUTING.md` lists the MSRV check in its tooling table and points
to the "Versioning" section. `docs/api-review.md`'s C-STABLE row now names the
README section in "Enforced by".

## Breaking changes

None. Builds on a toolchain older than 1.89 already failed (uuid); cargo now
names this crate first (`e2b-client@0.1.0 requires rustc 1.89`, checked with
1.88).
