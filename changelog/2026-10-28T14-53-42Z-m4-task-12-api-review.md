# M4 Task 12: API review (issue #95)

Plan: `docs/superpowers/plans/2026-10-28-milestone-4-api-stability.md`, Task 12.
Claims: CLM-0119, CLM-0179, CLM-0180.

## What was reviewed

Every item re-exported from `src/lib.rs` after Tasks 1 to 11, against the
Rust API Guidelines (C-CASE, C-CONV, C-GETTER, C-CTOR, C-COMMON-TRAITS,
C-BUILDER, C-DEBUG, C-SEND-SYNC, C-GOOD-ERR, C-NON-EXHAUSTIVE,
C-STRUCT-PRIVATE, C-STABLE, C-FAILURE). The record is the new
`docs/api-review.md`: one row per type and per constant, with a decision and
reason, an "Error display" section and the known limits from the plan's
Scope table.

## What changed

- `CommandEvent` and `Signal` are `#[non_exhaustive]`: envd's
  `process.ProcessEvent` and `process.Signal` can grow. The `Commands::start`
  example and `clm_0034_start_streams_chunks_then_exit` in
  `tests/live_commands.rs` gained a catch-all arm. Matches inside the crate
  stay exhaustive (the attribute only applies to other crates).
- `ConnectCode` and `PtySize` stay exhaustive, on purpose, and their rustdoc
  now says why: the gRPC codes are a closed set; a terminal size is two
  numbers.
- `new()` on the six options types that had only `Default`:
  `CommandOptions`, `PtyOptions`, `StreamInputOptions`, `WriteOptions`,
  `WatchOptions`, `FileUrlOptions`. Each is `Self::default()`.
- `Error::Decode` displays only `could not decode response`; the
  serde_json message is its `source()`, as `Error::Transport` does since
  Task 2. Before, `{:#}` in anyhow printed the serde_json message twice
  (brooke-reviews on PR #102).
- `Cargo.toml` gains `[lints.rust]` with `missing_docs` and
  `missing_debug_implementations` at `warn`; `clippy -D warnings` in
  `just lint` makes them errors. No item needed fixing.
- New `tests/api_traits.rs` (5 tests): `Send + Sync` on clients, service
  handles, options, results and errors; `Send` on the stream handles;
  `Debug` on every public type; `Error` and `TransportError` usable as
  `Box<dyn Error + Send + Sync>`/anyhow sources; `new() == default()` on
  every options type.
- New `a_decode_error_shows_its_detail_once` in `tests/error_taxonomy.rs`.

## Breaking changes

- A `match` on `CommandEvent` or `Signal` outside the crate needs a `_` (or
  `other => ...`) arm.
- `Error::Decode`'s `Display` was `could not decode response: <serde_json
  message>` and is now `could not decode response`. Print the chain
  (`{:#}` in anyhow, or walk `std::error::Error::source`) to see the detail.

## Why

The milestone fixes the surface 0.2.0 ships. Marking the protobuf-backed
enums `#[non_exhaustive]` now, before the release, means a new envd signal or
event kind is not a breaking change later. The `Decode` change makes the two
variants that wrap an error behave the same way under chain printers.
