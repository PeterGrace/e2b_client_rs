# M3 Task 2: Sandbox metrics (issue #61)

Plan: `docs/superpowers/plans/2026-10-27-milestone-3-lifecycle-parity.md`, Task 2.
Claims: CLM-0029 (S1), CLM-0155 (S4).

## What changed

- New module `src/metrics.rs`: `SandboxMetrics` (one sample: `timestamp`,
  `cpu_count`, `cpu_used_pct`, `mem_used`, `mem_total`, `mem_cache`,
  `disk_used`, `disk_total`; public fields, `#[non_exhaustive]`) and
  `MetricsParams` (optional `start` and `end`, sent as whole Unix seconds and
  omitted when unset). Both are re-exported from the crate root.
- `Client::get_sandbox_metrics(id, &MetricsParams)` calls
  `GET /sandboxes/{id}/metrics`; 404 is `Error::SandboxNotFound`, and a
  `null` body reads as no samples. `Sandbox::get_metrics(&MetricsParams)`
  delegates to it.
- Tests: mock tests `get_metrics_sends_start_and_end_as_unix_seconds`,
  `get_metrics_without_a_range_sends_no_query`,
  `get_metrics_with_a_null_body_is_empty` (added in review) and
  `get_metrics_of_a_missing_sandbox_is_not_found` (`tests/rest_metrics.rs`);
  unit tests `query_without_a_range_is_empty` and
  `query_sends_each_set_bound_as_unix_seconds`; doctests on `MetricsParams`
  and `Client::get_sandbox_metrics`; live test
  `clm_0029_get_metrics_reports_cpu_memory_and_disk`.
- Docs: "Metrics" and "Metric fields" rows in `docs/protocol-notes.md`
  ("REST endpoints"), metrics removed from that file's "Not implemented yet"
  bullet, and the CLM-0155 row in `docs/verification/s4-evidence-map.md`.

## Why the plan was corrected

- The plan's `MetricsParams` doctest called `Utc::now()`. The crate builds
  chrono without its `clock` feature, so the doctest did not compile
  (E0599). It now parses a fixed time; adding `clock` would have changed
  `Cargo.lock` for a doc example. The plan says so in a dated note.
- "Oldest first" in the `get_sandbox_metrics` rustdoc became "in the order
  the API returns them": neither SDK documents the order.
