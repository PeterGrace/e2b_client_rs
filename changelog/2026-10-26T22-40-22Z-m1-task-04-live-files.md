# M1 Task 4: live filesystem tests (S3)

Issue #8, Task 4 of `docs/superpowers/plans/2026-10-26-milestone-1-verify-v0.1.md`.

## What changed

- `tests/live_files.rs`: one live test per S3 v0.1 filesystem claim,
  CLM-0050 and CLM-0052 to CLM-0061, next to the existing `clm_0051`. Each is
  `#[tokio::test]`, `#[ignore]`d for live runs, uses its own `LiveSandbox` and
  asserts the ledger claim's statement:
  - `clm_0050`: 64 KiB covering every byte value survive `write` then `read`;
  - `clm_0052`: `write` returns a `WriteInfo` whose `path`, `name` and
    `file_type` (`FileType::File`) match the written file;
  - `clm_0053`: `read` of a missing file is an error with `is_not_found()`;
  - `clm_0054`, `clm_0055`: `list` at depth 1 returns exactly the direct
    entries with their types; at depth 2 it also returns `sub/b.txt`;
  - `clm_0056`: `get_info` reports size, file type, permissions and owner;
  - `clm_0057`: `exists` is true for a written file and false for a missing one;
  - `clm_0058`: `make_dir` returns true, then false for the same path;
  - `clm_0059`: `rename` returns the entry at its new path, the old path is
    gone and the content moved;
  - `clm_0060`: `remove` deletes a file, then its directory, and `exists` is
    false for both;
  - `clm_0061`: a file written as `root` is owned by `root`, one written as
    `user` by `user`.

The tests follow the plan's code. The only differences are cosmetic and need
no plan correction: assertion messages, a `files` local in the multi-call
tests, and `written` instead of `info` for the `WriteInfo` in `clm_0052`.
