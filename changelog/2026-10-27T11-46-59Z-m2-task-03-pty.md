# M2 Task 3: PTY sessions

Issue #32, Task 3 of `docs/superpowers/plans/2026-10-27-milestone-2-command-and-file-parity.md`.
Claims CLM-0047, CLM-0048, CLM-0049 (S2), CLM-0132, CLM-0133 and CLM-0134 (S4).

## What changed

- `Sandbox::pty()` returns a `Pty` (new `src/pty.rs`) with `create`,
  `connect`, `send_stdin`, `resize`, `kill` and `stream_input`. `create`
  starts `/bin/bash -i -l` on a PTY of the given `PtySize`. It adds
  `TERM=xterm-256color`, `LANG=C.UTF-8` and `LC_ALL=C.UTF-8` unless the
  caller set them, and sends no `stdin` field, as the SDKs do. `PtyOptions`
  holds the environment, working directory, user and stream deadline (60 s by
  default, `DEFAULT_PTY_TIMEOUT`).
- `PtyHandle::next_event` yields `PtyEvent::Data(Bytes)` for `data.pty` and
  `PtyEvent::Exit(CommandExit)`; `wait`, `send_stdin`, `resize` and `kill`
  act on the handle's pid. `CommandHandle` keeps ignoring `data.pty`, so PTY
  output and stdout/stderr never mix (plan Decision 2).
- `src/commands.rs`: `Commands::open`'s stream-opening code became the
  crate-level `open_process_stream`, which both handles use.
- `src/envd/process_pb.rs`: `PtyConfig`, `PtySizeWire`, `UpdateRequest`,
  `StartRequest.pty`, `StartRequest.stdin` as `Option<bool>` (commands still
  send `"stdin": false`), and `DataEvent.pty`.
- `src/stream_input.rs`: `InputKind::Pty` is now built, so its
  `#[expect(dead_code)]` is gone, and the rustdoc links to
  `crate::Pty::stream_input` are back.
- Tests: seven mock tests in `tests/envd_pty.rs`, unit tests for the PTY wire
  JSON and the env defaults, and three live tests in `tests/live_commands.rs`
  (`clm_0047`, `clm_0048`, `clm_0049`).
- Docs: a "PTY" section in `docs/protocol-notes.md` (PTY and `Update` are off
  the "Not implemented" list), rows for CLM-0132 to CLM-0134 in the S4
  evidence map, and CLM-0130 moved from `partial` to `yes`.

## Why it differs from the plan

The plan has been corrected in this same PR:

- The plan's `src/pty.rs` import list lacked `reqwest::header::HeaderMap` and
  `StreamInputOptions`; it is fixed inline.
- `tests/envd_pty.rs` is a superset of the plan's code: three more tests (the
  stdout/PTY separation that CLM-0133 states, `connect`, and `kill`), a user
  header and deadline check in the create test, and a whole-list comparison
  in the PTY stream-input test. A dated note in Step 1 lists them, and one in
  Step 6 lists the extra evidence-map entries.
- No test was added for `Commands::start` still sending `"stdin": false`:
  `run_streams_output_to_exit_code_with_sdk_headers` already asserts it, as
  the plan allowed.

Nothing that Task 4 (watch) uses changed: `within_request_timeout`,
`keepalive_headers()` and `server_stream` keep their signatures.
