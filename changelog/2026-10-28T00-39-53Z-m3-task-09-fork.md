# M3 Task 9: Fork (issue #68)

Plan: `docs/superpowers/plans/2026-10-27-milestone-3-lifecycle-parity.md`, Task 9.
Claims: CLM-0030 (S1, the fork half), CLM-0162 (S4).

## What changed

- `src/models.rs`: `ForkOptions` (`timeout`, `count`), `MAX_FORK_COUNT`
  (20), and the private wire types `ForkBody`, `ForkResultWire` and
  `ErrorBody`. `ForkOptions` and `MAX_FORK_COUNT` are re-exported from
  the crate root and named in the crate doc.
- `Client::fork_sandbox` (`POST /sandboxes/{id}/fork`, 404 → not found)
  returns `Vec<Result<Sandbox>>`, one result per fork; `Sandbox::fork`
  delegates with the sandbox's own id. The count is checked (1 to 20)
  before any request.
- Live helper `LiveSandbox::adopt`, so forks are killed on drop.
- Tests: 7 mock tests in `tests/rest_fork.rs`, 2 unit tests in
  `src/models.rs`, doctests on `ForkOptions` and `Client::fork_sandbox`,
  and the live test `clm_0030_fork_starts_running_copies`.
- Docs: the fork rows of "Snapshots and fork" in `docs/protocol-notes.md`,
  with fork dropped from its "Not implemented yet" bullet; the CLM-0162 row
  of `docs/verification/s4-evidence-map.md`; a dated correction in the
  plan's Task 9.

## Why

**Each fork entry is decoded on its own.** Every entry with a sandbox is a
running, billed sandbox. Decoding the 201 array in one go, as the plan had
it, would turn one malformed entry into an error for the whole call and drop
the handles of the forks that did start, so nobody could kill them. The
array is read as JSON values and each is decoded into its own
`Result`; a malformed entry is that fork's `Error::Decode`, or `Error::Protocol` with the sandbox ID when the entry has one, so a fork that may have started can still be killed (PR #83 review).

**Per-fork errors keep their code.** The SDK maps a per-fork code to an
exception class (and keeps a per-fork 404 generic, since the source was
found); the crate returns `Error::Api { status: code, message }` for every
code, so a per-fork 404 is never mistaken for `SandboxNotFound`. An error
wins over a sandbox in the same entry, and an entry with neither is
`Error::Protocol`, as the SDK's `error is not None or sandbox is None`.

**Forks carry the source's metadata.** On hosted E2B both forks'
`get_info().metadata` had the run's `e2b-client-test` key, so the sandbox
sweep finds a leaked fork. The live test asserts it.
