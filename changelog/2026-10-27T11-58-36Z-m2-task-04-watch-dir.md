# M2 Task 4: Directory watching

Issue #33, Task 4 of `docs/superpowers/plans/2026-10-27-milestone-2-command-and-file-parity.md`.
Claims CLM-0063 (S3), CLM-0135 and CLM-0136 (S4).

## What changed

- `Filesystem::watch_dir(path, &WatchOptions) -> WatchHandle` over envd's
  server-streaming `filesystem.Filesystem/WatchDir`. It sends the user header
  and `Keepalive-Ping-Interval: 50`, bounds the whole watch with the options'
  timeout (60 s by default, `DEFAULT_WATCH_TIMEOUT`), and waits for the
  opening `start` event within the request timeout through the shared
  `within_request_timeout`. Anything else as the first message is
  `Error::Protocol`.
- `WatchOptions` holds `recursive`, `include_entry`, `allow_network_mounts`,
  `user` and `timeout`. The three flags are refused with
  `Error::InvalidArgument` on envd older than 0.1.4, 0.6.3 and 0.6.4, before
  any request is sent (new `EnvdVersion::RECURSIVE_WATCH`,
  `FS_EVENT_ENTRY_INFO`, `WATCH_NETWORK_MOUNTS`).
- `WatchHandle::next_event` yields `FilesystemEvent {name, event_type,
  entry}`, with `FilesystemEventType::{Create, Write, Remove, Rename,
  Chmod}`. It skips keepalives and unspecified or unknown types, as the SDKs
  do, and returns `None` on a clean end. Dropping the handle stops the watch.
- `src/envd/filesystem_pb.rs`: `WatchDirRequest`, `WatchDirResponse`,
  `FilesystemEventWire`.
- Tests: four mock tests in `tests/envd_watch.rs`, four unit tests, and the
  live test `clm_0063_watch_dir_reports_a_created_file` in
  `tests/live_files.rs`. The live test looks for the create event of its own
  file, because envd can send a burst of events.
- Docs: a "Directory watching" section in `docs/protocol-notes.md` (watching
  is off the "Not implemented" list), and rows for CLM-0135 and CLM-0136 in
  the S4 evidence map.

## Why it differs from the plan

The plan has been corrected in this same PR:

- `WatchDirResponse.start` is `Option<Empty>` (the crate's existing
  `connect::Empty`), not `Option<serde_json::Value>`: it is `Clone`, skips
  unknown fields, and needs no JSON value allocated. Fixed inline.
- The version gates moved from `watch_dir` into the private
  `WatchOptions::check_supported`, so a unit test can check them without a
  server. Fixed inline.
- The live test matches the create of `new.txt` and collects the other
  events for its failure message, instead of taking the first create of
  any name. Fixed inline.
- The tests are a superset of the plan's: header and deadline checks in
  the first mock test, a test that the open is bounded by the request
  timeout, and four unit tests. Dated notes in Steps 1 and 5.
- Task 7 gained a note: `include_entry` events carry `EntryInfoWire`, so
  they pick up its `metadata` field with no further change.

`server_stream`, `within_request_timeout` and `keepalive_headers()` are
reused unchanged.
